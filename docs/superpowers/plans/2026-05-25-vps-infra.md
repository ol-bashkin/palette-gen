# VPS Infrastructure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Migrate palette-gen.app from Vercel to a self-hosted Ubuntu 24.04 VPS with Docker Compose, host nginx + Certbot SSL, and GitHub Actions CI/CD.

**Architecture:** Each project gets an isolated Docker Compose stack in `/srv/<domain>/`. Host nginx is the sole internet-facing entry point, terminates SSL, and reverse-proxies to containers bound to `127.0.0.1`. GitHub Actions builds a Docker image on every push to main, pushes to GHCR, and SSH-deploys to the VPS.

**Tech Stack:** Docker, Docker Compose, nginx (host + container), Certbot, GitHub Actions, GHCR, Ubuntu 24.04.

## Task 1: Dockerfile and internal nginx config

**Files:**
- Create: `docker/nginx.conf`
- Create: `Dockerfile`

- [ ] **Step 1: Create the internal container nginx config**

Create `docker/nginx.conf`:

```nginx
server {
    listen 80;
    root /usr/share/nginx/html;
    index index.html;
    location / {
        try_files $uri $uri/ /index.html;
    }
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
}
```

- [ ] **Step 2: Create the Dockerfile**

Create `Dockerfile` in the repo root:

```dockerfile
FROM node:22-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

FROM nginx:alpine
COPY --from=build /app/dist /usr/share/nginx/html
COPY docker/nginx.conf /etc/nginx/conf.d/default.conf
EXPOSE 80
```

- [ ] **Step 3: Build the image locally**

```bash
docker build -t palette-gen-test .
```

Expected: build completes, final image is `nginx:alpine` based, no errors.

- [ ] **Step 4: Run the container and verify SPA routing**


In another terminal:

```bash
# Expected: 200
```

Stop the container with `Ctrl+C`.

## Task 2: GitHub Actions deploy workflow

**Files:**
- Create: `.github/workflows/deploy.yml`

- [ ] **Step 1: Create the workflows directory**

```bash
mkdir -p .github/workflows
```

- [ ] **Step 2: Create the workflow file**

Create `.github/workflows/deploy.yml`:

```yaml
name: Deploy

on:
  push:
    branches: [main]

jobs:
  build-and-push:
    runs-on: ubuntu-latest
    permissions:
      contents: read
      packages: write
    steps:
      - uses: actions/checkout@v4

      - name: Log in to GHCR
        uses: docker/login-action@v3
        with:
          registry: ghcr.io
          username: ${{ github.actor }}
          password: ${{ secrets.GITHUB_TOKEN }}

      - name: Build and push
        uses: docker/build-push-action@v6
        with:
          push: true
          tags: ghcr.io/olegbashkin/palette-gen:latest

  deploy:
    needs: build-and-push
    runs-on: ubuntu-latest
    steps:
      - name: Deploy on VPS
        uses: appleboy/ssh-action@v1
        with:
          host: ${{ secrets.VPS_HOST }}
          username: ${{ secrets.VPS_USER }}
          key: ${{ secrets.VPS_SSH_KEY }}
          script: |
            cd /srv/palette-gen.app
            docker compose pull
            docker compose up -d
            docker image prune -f
```

- [ ] **Step 3: Commit (do NOT push yet — server isn't ready)**

```bash
git add .github/workflows/deploy.yml
git commit -m "feat: add GitHub Actions build and deploy workflow"
```

## Task 3: Server bootstrap (run via SSH as root)

These are one-time manual steps on the VPS. SSH in as root first.

**Prerequisites:** You have root SSH access to the second VPS IP.

- [ ] **Step 1: Update packages**

```bash
apt update && apt upgrade -y
```

- [ ] **Step 2: Configure UFW firewall**

```bash
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
```

Verify:
```bash
ufw status
# Expected: Status: active, with 22, 80, 443 ALLOW
```

- [ ] **Step 3: Harden SSH**

Edit `/etc/ssh/sshd_config` and set these two lines (they may already exist, change the values):

```
PermitRootLogin no
PasswordAuthentication no
```

**IMPORTANT:** Before restarting SSH, open a second SSH session and verify you can still log in with your key. Only then:

```bash
systemctl restart ssh
```

- [ ] **Step 4: Install Docker**

```bash
apt install -y ca-certificates curl
install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg -o /etc/apt/keyrings/docker.asc
chmod a+r /etc/apt/keyrings/docker.asc

echo "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.asc] \
  https://download.docker.com/linux/ubuntu $(. /etc/os-release && echo "$VERSION_CODENAME") stable" \
  | tee /etc/apt/sources.list.d/docker.list > /dev/null

apt update
apt install -y docker-ce docker-ce-cli containerd.io docker-compose-plugin
```

Verify:
```bash
docker --version
# Expected: Docker version 27.x.x or newer

docker compose version
# Expected: Docker Compose version v2.x.x
```

- [ ] **Step 5: Install nginx and Certbot**

```bash
apt install -y nginx certbot python3-certbot-nginx
```

Verify:
```bash
systemctl status nginx
# Expected: active (running)
```

- [ ] **Step 6: Create deploy user**

Generate a dedicated SSH key pair on your local machine (not on the server):

```bash
# Run this LOCALLY, not on the server
ssh-keygen -t ed25519 -C "palette-gen-deploy" -f ~/.ssh/palette-gen-deploy
# Do not set a passphrase — GitHub Actions needs passwordless access
```

This creates `~/.ssh/palette-gen-deploy` (private) and `~/.ssh/palette-gen-deploy.pub` (public).

Back on the server:

```bash
adduser --disabled-password --gecos "" deploy
usermod -aG docker deploy
mkdir -p /home/deploy/.ssh
chmod 700 /home/deploy/.ssh
```

Paste the contents of your local `~/.ssh/palette-gen-deploy.pub` into:
```bash
echo "PASTE_PUBLIC_KEY_HERE" > /home/deploy/.ssh/authorized_keys
chmod 600 /home/deploy/.ssh/authorized_keys
chown -R deploy:deploy /home/deploy/.ssh
```

Verify from your local machine:
```bash
ssh -i ~/.ssh/palette-gen-deploy deploy@<VPS-IP> "whoami"
# Expected: deploy
```

- [ ] **Step 7: Create project directory**

```bash
mkdir -p /srv/palette-gen.app
chown deploy:deploy /srv/palette-gen.app
```

- [ ] **Step 8: Create production docker-compose.yml**

As `deploy` user (or set ownership after):
```bash
cat > /srv/palette-gen.app/docker-compose.yml << 'EOF'
services:
  web:
    image: ghcr.io/olegbashkin/palette-gen:latest
    restart: unless-stopped
    ports:
      - "127.0.0.1:8080:80"
EOF
chown deploy:deploy /srv/palette-gen.app/docker-compose.yml
```

## Task 4: infra repo — nginx site config

This is a **new GitHub repository** called `infra`, separate from `palette-generator`.

- [ ] **Step 1: Create the repo locally and on GitHub**

```bash

gh repo create olegbashkin/infra --private --source=. --push
```

- [ ] **Step 2: Create the nginx site config**

```bash
mkdir -p nginx/sites
```

Create `nginx/sites/palette-gen.app.conf`:

```nginx
server {
    listen 80;
    server_name palette-gen.app www.palette-gen.app;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    server_name palette-gen.app www.palette-gen.app;

    ssl_certificate     /etc/letsencrypt/live/palette-gen.app/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/palette-gen.app/privkey.pem;
    include             /etc/letsencrypt/options-ssl-nginx.conf;

    add_header X-Content-Type-Options  "nosniff"                         always;
    add_header X-Frame-Options         "DENY"                            always;
    add_header Referrer-Policy         "strict-origin-when-cross-origin" always;

    location / {
        proxy_pass         http://127.0.0.1:8080;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
    }
}
```

## Task 5: First deploy and SSL

At this point: repo has Dockerfile + deploy.yml, server is bootstrapped, nginx config is in place.

- [ ] **Step 1: Add GitHub Secrets**

Go to `github.com/olegbashkin/palette-generator` → Settings → Secrets and variables → Actions → New repository secret:

| Name | Value |
|---|---|
| `VPS_HOST` | VPS second IP address |
| `VPS_USER` | `deploy` |
| `VPS_SSH_KEY` | Contents of `~/.ssh/palette-gen-deploy` (private key) |

- [ ] **Step 2: Make the GHCR package public**

GHCR packages are private by default. After the first push (next step), go to:
`github.com/olegbashkin?tab=packages` → `palette-gen` → Package settings → Change visibility → Public

This allows the server to pull without authentication. Alternatively, add a `docker login` step to the deploy script using a PAT — but public is simpler for an open-source project.

- [ ] **Step 3: Push to main to trigger the first pipeline**

```bash
# In palette-generator repo
git push origin main
```

Go to the Actions tab on GitHub and watch the pipeline. Both `build-and-push` and `deploy` jobs must be green.

Expected sequence:
1. `build-and-push`: ~2-3 minutes (npm ci + vite build + docker push)
2. `deploy`: ~20 seconds (docker compose pull + up)

- [ ] **Step 4: Verify the container is running on the server**

```bash
ssh deploy@<VPS-IP> "docker ps"
# Expected: palette-gen_web_1 container, Up X seconds, 127.0.0.1:8080->80/tcp

curl -s -o /dev/null -w "%{http_code}" http://<VPS-IP>:8080
# Expected: 200  — but only works if port 8080 is accessible; it won't be (UFW blocks it)
# Instead verify via nginx on the server itself:
ssh deploy@<VPS-IP> "curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8080"
# Expected: 200
```

- [ ] **Step 5: Change DNS A record**

In your DNS provider, change the A record for `palette-gen.app` and `www.palette-gen.app` from the Vercel IP to the VPS second IP.

Wait for propagation (check with `dig palette-gen.app +short` — when it returns the VPS IP, proceed).

- [ ] **Step 6: Obtain SSL certificate**

On the server as root:

```bash
certbot --nginx -d palette-gen.app -d www.palette-gen.app
```

Certbot will:
1. Validate domain ownership via HTTP-01 challenge
2. Obtain certificate from Let's Encrypt
3. Automatically modify the nginx config to add SSL directives

After certbot, reload nginx:
```bash
nginx -t && systemctl reload nginx
```

- [ ] **Step 7: Verify HTTPS end-to-end**

```bash
curl -s -o /dev/null -w "%{http_code}" https://palette-gen.app
# Expected: 200

curl -s -o /dev/null -w "%{http_code}" http://palette-gen.app
# Expected: 301 (redirect to HTTPS)
```

Open `https://palette-gen.app` in a browser and verify the site loads correctly, including navigating to a non-root route and refreshing (SPA routing test).
